## 3. ⚠️ CRITICAL: the reporting-reliability issue (root fix still owed)

**Symptom:** the Performance/State-of-SEO dashboards periodically show **all zeros**.
**Cause:** the GSC OAuth app is in Google **"Testing"** publishing mode → the refresh token **expires every ~7 days**. When it's expired, the weekly cron (04:00 UTC Mon, + others) pulls GSC, gets an auth error, and — before the fix — **overwrote good data with zeros**. This bit the reports **4+ times** this session.

**What's fixed (v7.9.108):** `monthly-trend-background` and `page-registry-background` now **respect the GSC error** and **never overwrite good data with zeros** — they preserve last-good and self-heal on the next good run. So a blip no longer flatlines the dashboard.

**What's still owed (USER/DEV action — not codeable here):** move the OAuth app **Testing → Production** (or set User type **Internal** if all users are `@yolkbrands.com` Workspace) in **Google Cloud Console → APIs & Services → OAuth consent screen**. Internal apps / Production apps don't expire the token weekly. After changing, **reconnect GSC once** in the Nest. Until this is done, the connection still drops for ~a day between crons (hardening keeps data intact, but live pulls fail).

**When data looks zeroed:** fire `/.netlify/functions/monthly-trend-background?full=1` and `/.netlify/functions/page-registry-background?brand=<brand>` (POST, session cookie auths `authorizeJob`) to rebuild from live GSC. Confirm GSC is live first via `/api/market-traffic?brand=bonbird`.

## 7. Key gotchas / landmines (don't relearn these)

- **GSC 7-day token expiry** (§3) — the #1 reliability trap.
- **schedule-403 trap:** a Netlify function with a `schedule` 403s ALL direct HTTP calls. `content-outcomes-background` is schedule-trapped (Mon 6am) — can't be manually fired; it runs on its cron. `monthly-trend-background` + `page-registry-background` ARE HTTP-firable (session cookie → `authorizeJob`).
- **GSC lag ≠ gone:** Google reports a URL for weeks after it 404s. This caused phantom "indexed" pages + phantom ranking drops. The registry now HTTP-checks out-of-sitemap URLs and marks **redirect** / **gone (404/410)** → excludes them from the live set; redirect impressions are **folded into the target**. Content filters (`ocIsContent` / `isContentPage` + `UTIL_RE`) exclude legal/terms/giveaway/utility pages from findings.
- **URL Inspection API verdict lags the live GSC UI** — it reported "Submitted and indexed" for pages the live check showed as not-indexed. Trust the behavioural signal (in-sitemap + live + 0 impressions + aged) over the API verdict; the API verdict is supporting detail only.
- **`site:` search is unreliable** for deep URLs — don't use it to judge indexation; use URL Inspection (live test) / behavioural signal.
- **Background fn 202 ≠ ran successfully** — `authorizeJob` can 401 internally after the 202 ack. Verify the write (builtAt, data) before claiming success.
- **Pickl = dev-first**, Bonbird writes went to prod via the Nest pipeline. Live meta writes use `wordpress.js` `update_meta` (title/desc only, never body — the body-writable guard prevents the `/ae/` homepage-clobber class of bug).
